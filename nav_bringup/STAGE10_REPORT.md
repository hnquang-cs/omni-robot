## Stage 10 Revision: LiDAR Navigation Goal Failure

### 1. Problem

- Manual Gazebo controller motion works, including returning the robot to `x=0.0, y=0.0, yaw=0.0`.
- `move_base` does not drive to the test goal `x=1.0, y=1.0, yaw=0.0`.
- A previous `move_base` run reported: `Failed to find a valid plan. Even after executing recovery behaviors.`
- The map used for navigation was reported as small and missing one wall.

### 2. Diagnosis Workflow

Run:

```bash
roscd nav_bringup
./scripts/diagnose_goal_failure_stage10.sh
rosrun nav_bringup check_goal_on_map.py --x 1.0 --y 1.0 --yaw 0.0
./scripts/test_goal_1_1_stage10.sh
```

The diagnosis checks:

- `/map`, `/lidar/scan`, `/odom`, `/amcl_pose`, `/move_base/status`, global/local costmaps.
- TF chain `map -> odom -> base_footprint -> base_link -> lidar_link`, with `odom -> base_link` fallback.
- Whether the goal and current AMCL pose are inside map bounds and in free space.
- Footprint, inflation, local obstacle source, planner plan topics, and `/cmd_vel` after sending the goal.

If `check_goal_on_map.py` returns `OUT_OF_BOUNDS`, `UNKNOWN`, or `OCCUPIED`, do not force the planner to run. Regenerate the wide map or choose a goal in free space.

## Stage 10 Forward-Only Correction

Updated assumption: the current robot is not allowed to move sideways or in reverse. Stage 10 now includes a separate forward-only navigation profile:

- `nav_bringup/config/teb_forward_only.yaml`
- `nav_bringup/launch/move_base_teb_forward_only.launch`
- `nav_bringup/launch/navigation_lidar_forward_only.launch`
- `omni_base_controller/scripts/cmd_vel_forward_only_filter.py`
- `omni_base_controller/config/cmd_vel_forward_only_filter.yaml`
- `omni_base_controller/launch/cmd_vel_forward_only_filter.launch`

Command policy:

- `linear.x >= 0`
- `linear.y = 0`
- `angular.z` is allowed but clamped to `max_vel_theta`
- planner output is visible at `/cmd_vel_raw`
- filtered controller input is `/cmd_vel`

The TEB profile discourages invalid motion using `max_vel_x_backwards=0.0`, `max_vel_y=0.0`, `allow_init_with_backwards_motion=false`, `weight_kinematics_forward_drive=1000.0`, and `weight_kinematics_nh=1000.0`.

The forward-only filter is the final safety layer. It clamps negative `linear.x` to zero, forces `linear.y=0`, zeros unused axes, limits `angular.z`, and rate-limits `linear.x` and `angular.z`.

Acceptance scripts:

- `nav_bringup/scripts/check_cmd_vel_forward_only.sh`
- `nav_bringup/scripts/test_goal_forward_only_stage10.sh`
